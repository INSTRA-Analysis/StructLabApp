# 10. Reference

## 10.1 Files and folders

### The .slab file

A model is saved as one `.slab` file: plain JSON text, so it can be read, compared in
version control and generated by scripts. It holds:

| Key | Contents |
|---|---|
| `version` | File format version (3 today) |
| `metadata` | Project information (File → Project Info) |
| `analysis_mode`, `mode_3d` | Plane frame or space frame |
| `nodes` | Coordinates, support, spring stiffnesses |
| `members` | End nodes, element type, group, E, A, I, I_y, J, β, sub-elements, density, strengths and design data |
| `load_cases` | Name, category, alternative group, nodal and member loads, self-weight |
| `combinations` | Name, limit state, factor per case |
| `crossing_braces` | Model → Crossing Bracing Connected |

Values are stored in SI base units: metres, newtons, pascals, kg/m³. The window shows them
in the units of 10.5.

**Older files.** Versions 1 and 2 open as well. A model from a 2D version of StructLab
(drawn in X and Y, Y up) opens as a plane frame in the XZ plane, Z up, with the same loads; saving writes it in the current format.

### Where StructLab keeps things

| What | Where |
|---|---|
| Autosave (every 2 minutes) | `.structlab\autosave.slab` in your user folder |
| Recent files list | `.structlab\recent_files.json` in your user folder |
| Interface preferences | Windows registry, `HKEY_CURRENT_USER\Software\INSTRA Analysis\StructLab` |

## 10.2 CSV import

**File → Import → From CSV…** builds a model from one text file with four labelled
sections. It is the quickest way to bring in geometry from a spreadsheet or another program.

```
# lines starting with # are comments; blank lines are ignored
#NODES
id,x,y,z
1,0,0,0
2,0,0,4.5
#MEMBERS
id,node_i,node_j,etype,group,E,A,I,Iy,J,fy,density
1,1,2,beam,Column,2.1e11,5.381e-3,8.356e-5,,,2.75e8,7850
#SUPPORTS
node,rx,ry,rz
1,1,1,1
#FORCES
node,Fx,Fy,Fz
2,15000,0,0
```

- Each section starts with a row of column names; columns are found by name, so their order
  does not matter.
- **Units are SI**: m, N, Pa, kg/m³. **Z is up**; a downward force is a negative Fz. The
  importer does not rotate anything.
- **Ids** are your own labels, in any order; StructLab renumbers them.
- **etype**: `bar` (pinned at both ends, axial only; the default), `beam`, `pin_i` or
  `pin_j` (released at one end).
- **I, Iy, J** are needed only for beams; Iy defaults to I. **W_pl** and **W_el** may be
  added for the design checks.
- **group** is a free label, used by the Groups panel, colours and Optimise.
- **Supports**: rx, ry, rz hold (1) or free (0) the three translations. `1,1,1` is a fixed
  support and `1,1,0` a roller free in Z; any other set is imported as exactly those
  translations held.
- **Forces** go into the first load case. Member loads, moments, other load cases and
  combinations are added in the window afterwards.
- Rows that cannot be used (an unknown node, a bad number) are skipped and listed in a
  summary; the rest of the model still loads.

An imported model is a space frame. For a plane structure, put every node at y = 0 and turn
on **Analysis → Plane Frame (XZ)** after the import. Do not lay a plane frame flat in XY: it
would bend about its members' weak axis.

The `examples` folder has several files to start from, including `truss_template.csv`.

## 10.3 Python

### The Python console

**Ctrl+\`** (or **Python Console** on the Tools tab) opens an IPython console inside StructLab, also in
the Windows build. These names are ready to use:

| Name | What it is |
|---|---|
| `model` | The open model, as an SDK model (below); changes act on the model in the window |
| `state` | The model's raw data: nodes, members, load cases |
| `sdk` | The SDK module, to build other models |
| `np`, `plt` | NumPy and Matplotlib |
| `solve()` | Runs the window's Solve: results panel and diagrams |
| `refresh()` | Redraws the window after you change `state` or `model` |

### The SDK

From the source code, `sdk.py` builds and solves models without the window: parametric
studies, checks of hand calculations, batch runs.

```python
import sdk as sl

m = sl.Model()                       # a plane frame in XZ; sl.Model("space") for 3D
a = m.add_node(0, 0, 0)              # x, y, z in m (y = 0 in a plane frame)
b = m.add_node(6, 0, 0)
m.pin(a)
m.roller(b)                          # free in X
beam = m.add_member(a, b, E=210e9, A=5.381e-3, I=8.356e-5)
m.add_udl(beam, w=10e3)              # N/m, downward

r = m.solve()
print(r.reactions(a)[2] / 1e3)       # vertical reaction: 30.0 kN
print(r.max_moment(beam) / 1e3)      # 45.0 kN·m
r.plot("BMD").savefig("bmd.png")
```

| Model method | Does |
|---|---|
| `add_node(x, y, z)` | Adds a node, returns its id |
| `fixed`, `pin`, `roller`, `roller_y`, `roller_z` | Supports (roller: free in X; roller_y: free in Y; roller_z: free vertically) |
| `add_member(i, j, E, A, I, I_y=None, J=0, n_sub=4, element_type="BEAM")` | Adds a member; type `BEAM`, `BAR`, `PIN_LEFT` or `PIN_RIGHT` |
| `add_load_case(name, category)` | A load case; category `G`, `Q`, `W`, `S` or `E` |
| `add_point_load(node, Fx, Fy, Fz, Mx, My, Mz, lc=None)` | Nodal load, global axes |
| `add_udl(member, w, direction="w", lc=None)` | Uniform load: `w` local (downward positive), `qx`, `qy`, `qz` global |
| `add_varying_load(member, w_start, w_end, ...)` | Linearly varying load |
| `add_partial_load(member, w, start, end, lc=None)` | Load over part of the length (fractions 0 to 1) |
| `add_point_force_on_member(member, magnitude, position, lc=None)` | Point force at a fraction of the length, downward positive |
| `solve(lc=None)` | Solves one load case and returns its results |

| Result method | Gives |
|---|---|
| `reactions(node)` | [Fx, Fy, Fz, Mx, My, Mz] in N and N·m |
| `displacement(node)` | [dx, dy, dz, θx, θy, θz] in m and rad |
| `member_forces(member)` | End forces in local axes (N positive = compression) |
| `max_moment(member)`, `max_shear(member)` | Largest value along the member |
| `plot("BMD" / "SFD" / "AFD", member_id=None)` | A Matplotlib figure |

The SDK works in SI base units (N, m, Pa). Loads given with `lc="name"` create that case
if it does not exist. `sdk_examples/` has two complete scripts.

## 10.5 Units and sign conventions

### Units in the window

| Quantity | Unit |
|---|---|
| Coordinates, lengths | m |
| Forces, reactions | kN |
| Moments | kN·m |
| Distributed loads | kN/m |
| E | GPa |
| A | m² |
| I, I_y, J | ×10⁻⁶ m⁴ |
| W<sub>pl</sub>, W<sub>el</sub> | cm³ |
| Concrete b, h, cover | mm; reinforcement As in mm² |
| Strengths fy, fck, fyk | MPa |
| Density | kg/m³ |
| Displacements, rotations | mm, mrad |

### Axes

- **Global axes**: X and Y horizontal, **Z up**. A plane frame lies in the XZ plane.
- **Freedoms per node**: space frame dx, dy, dz, θx, θy, θz; plane frame dx, dz, θy.
- **Rotations and moments** follow the right-hand rule about the global axes.
- **Member local axes**: x from the first node to the second; y and z as shown by
  **View → Local Axes** and turned by the β angle (chapter 3).

### Loads

| Load | Positive |
|---|---|
| Nodal force Fx, Fy, Fz | Along +X, +Y, +Z: a downward load is a **negative** Fz |
| Nodal moment | Right-hand rule about the global axis |
| Member load **w**, point force on a member | Towards the member's local −y: **downwards** on a horizontal member |
| Member load **qx**, **qy** | Along +X, +Y |
| Self-weight | Always along −Z |

### Results

| Result | Positive |
|---|---|
| Displacements, reactions | Along the global axes |
| Member axial force N | **Compression** at the first end (N_i); the second end carries the opposite sign |
| Bending moment M | **Sagging**: tension on the member's bottom face (local −y side) |
| Bending moment diagram | Drawn on the **tension side**: sagging below a beam, hogging above |
| Shear force diagram | Positive above the member; a downward point load steps it down |
| Axial force diagram | Compression red, tension blue |

## 10.6 Limitations

**Analysis** (chapter 6.5)
- Linear elastic, first order: no P-Δ, no buckling analysis, no cables or tension-only
  members, no material non-linearity, no dynamics.

**Design checks** (chapter 8)
- Equal steel angles: flexural buckling, tension on the gross section and elastic bending.
  Torsional-flexural buckling, end-connection eccentricity, net section and connections are
  not checked.
- Other steel sections: cross-section only, no member buckling or lateral-torsional
  buckling.
- Concrete: EN 1992-1-1 6.1 section resistance only; slenderness not checked. Timber:
  bending only.
- Optimise chooses equal angles only, and runs as a script.

**Loads and combinations** (chapter 5)
- Combinations follow EN 1990 Table A1.2(B) with the recommended factors; every companion action is
  taken both with and without. There are no seismic actions yet (Dynamic Analysis module).
- A load case's name and category, and its alternative group, cannot be changed in the
  window.
- Member loads are per metre of member length; there is no load per metre on plan for
  sloping members.

**Model and sections**
- The section library gives I_y and J for angles only; enter them for other sections in a
  space frame.
- CSV import reads nodes, members, translational supports and nodal forces in one load
  case.

**Report**
- Very long tables in the PDF report are cut to fit their page.
